# go-fund-operations

开放式基金申购受理与估值日批处理服务。

开发环境：Go 1.23.0。

运行测试：

    go test ./...

## 交易日与估值日

交易日历（`Calendar`）记录基金开放的交易日；估值日是申购申请被确认份额时
所采用的净值所属日期。两者关系如下：

- 投资者在交易日的每日截止时间（`Fund.CutoffTime`，按 `Fund.Timezone` 时区、
  统一时钟 `Clock` 判断）之前或恰在截止时刻提交，申请归入**当日**估值日批次；
- 截止之后或非交易日提交，申请顺延归入**下一个交易日**的估值日批次；
- 批次关闭后，申请集合、估值日与采用的净值版本被冻结，迟到申请
  （`ErrBatchClosed`）不能重新打开已关闭的批次。

## 精度与舍入规则

- 金额单位为 0.01 元（分），净值单位为 0.0001 元，份额单位为 0.01 份；
- 确认份额 = floor(金额 × 10000 / 净值)，一律向下舍入；
- 确认金额 = floor(份额 × 净值 / 10000)，舍入差额（申购金额 − 确认金额）
  按固定方式留存基金资产，并逐笔记录在申请与批次快照中，保证可追溯；
- 净值更正产生递增的新版本，已确认批次仍引用冻结的旧版本，原结果不被改写。

## 接口概览

- `RegisterFund` / `SetFundStatus`：基金登记与交易状态切换；已暂停交易、
  币种不符、金额低于起点的申请会被拒绝，不进入待处理批次；
- `Subscribe`：申购受理。相同外部申请号重复提交时，内容一致返回原申请
  （含已确认结果），内容不一致返回 `ErrConflict`；
- `PublishNAV` / `CloseBatch` / `ConfirmBatch`：发布净值、关闭批次
  （冻结快照）、按冻结净值确认份额；关闭与确认均幂等；
- `GetApplication` / `GetBatch`：结果查询。

并发安全：`Service` 所有方法持有互斥锁，批次关闭、净值确认与重复请求并发时，
一笔申请只得到一个最终结果，不会出现重复份额或半笔确认。

持久化：`Persister` 接口支持状态快照持久化，`NewFileService` 以 JSON 文件
（临时文件 + 原子改名）保存基金、申请、批次快照与净值版本，重启后可完整恢复。
