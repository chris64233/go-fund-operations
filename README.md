# go-fund-operations

开放式基金交易与估值服务的 Go 项目基础模块。

开发环境：Go 1.23.0。

运行测试：

    go test ./...

## dividend 包：分红与红利再投资

`dividend` 实现开放式基金分红的完整生命周期：

```
DRAFT → CONFIRMED → EXECUTING → EXECUTED
  └────────┴── CANCELLED(仅执行前可取消)
```

### 核心规则

- **登记快照**：方案确认（`ConfirmPlan`）时按登记日冻结持有人份额快照；
  登记日之后的交易不改变本次分红资格，登记日（含）之前的补登交易被拒绝。
- **领取方式**：持有人可选择现金领取或红利再投资（默认现金），
  执行开始前可反复修改，执行开始后锁定。
- **精度与舍入**（定点数，金额到分、份额到 0.01 份、单价到 1e-6 元）：
  - 现金红利 = 登记份额 × 每份分红，四舍五入到分；
  - 再投资份额 = 现金红利 ÷ 除息净值，向下取整到 0.01 份；
  - 折算差额以现金补齐，保证 Σ明细应发 = Σ实发现金 + Σ新增份额折算 = 方案总额。
- **幂等与冲突**：以方案号为幂等键。重复执行返回原执行结果；
  基金、登记日、每份分红或除息净值不一致时返回 `ErrExecutionConflict`。
- **中断恢复**：执行中断后方案停留在 `EXECUTING`，再次执行只补齐
  未完成明细；入账凭幂等键去重，不会重复发放现金或重复增加份额。
- **取消与更正**：仅执行前可取消，取消后快照与选择记录仍可查询；
  已执行方案不得删除分配明细，只能通过独立更正记录（`PostCorrection`）调整。
- **并发**：方案状态迁移串行化，明细逐条幂等入账；执行、持仓变动与
  查询并发时，每名持有人只生成一份最终分配。每次状态变化均持久化到
  `StatusHistory`。

### 主要接口

| 方法 | 说明 |
| --- | --- |
| `PostTrade` | 登记申购/赎回交易（带交易日，用于登记日快照） |
| `CreatePlan` | 创建分红方案（基金、登记日、除息日、每份分红、除息净值） |
| `SetChoice` | 设置/修改持有人领取方式（执行前） |
| `ConfirmPlan` | 确认方案并冻结登记日快照 |
| `Execute` | 执行/恢复执行，幂等返回 `ExecutionResult` |
| `CancelPlan` | 执行前取消方案 |
| `PostCorrection` | 对已执行方案登记独立更正记录 |
| `GetPlan` / `Snapshot` / `Choices` / `Allocations` / `Execution` / `StatusHistory` / `Corrections` | 查询接口 |
| `Holdings` / `CashBalance` | 持有人份额与现金余额查询 |

### 测试覆盖

`dividend/` 下的测试覆盖：登记日边界、现金与再投资精度及总额守恒、
重复执行幂等与参数冲突、中断恢复、取消与执行竞态、并发执行下分配唯一性。
