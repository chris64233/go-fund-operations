# go-fund-operations

开放式基金交易与估值服务的 Go 项目基础模块。

开发环境：Go 1.23.0。

运行测试：

    go test ./...

## 代销机构汇总交易分配（omnibus 包）

机构先提交一笔总额汇总订单，再在截止前陆续补齐客户明细；
客户分配合计必须始终与机构订单一致。

### 模型

- `Order`：汇总订单，记录机构、基金、交易方向（申购按总金额、赎回按总份额）、
  估值日、外部编号与版本号。相同机构与外部编号重复登记返回已有订单（幂等）。
- `Allocation`：客户分配明细（客户号 + 分配数量）。同一客户可修改尚未冻结的
  明细（覆盖而非累加），不会形成重复有效分配。
- `FreezeRecord`：冻结结果，保存按客户号稳定排序的分配快照。

### 流程

1. `CreateOrder` 登记汇总订单，订单进入 `OPEN`。
2. `UpsertAllocation` / `RemoveAllocation` 维护客户明细；每次变更推进订单版本，
   调用方须携带所见版本，版本不一致返回 `ErrVersionConflict`，以此裁决并发修改。
3. `Freeze` 校验客户明细总和与订单总量严格一致：存在缺口、超额或不合格客户
   （空客户号、非正数量）时整笔不能冻结，未分配部分不允许挂到虚拟客户。
   成功后保存稳定排序快照，订单进入 `FROZEN`。
4. `Confirm` 确认订单：成功则按冻结快照生成客户持仓（`CONFIRMED`）；
   失败则订单进入 `FAILED`，客户明细保留查询但不生成任何份额。
   冻结后迟到的明细修改一律被拒绝，不得改变已确认客户持仓。

### 查询

- `GetOrder`：汇总订单；`Allocations`：当前有效客户分配；
- `FreezeRecordOf`：冻结快照；`Gap`：总量与已分配差额（正为缺口、负为超额）；
- `Holding`：客户已确认持仓（未确认或失败订单恒为 0）。

### 测试

`omnibus/omnibus_test.go` 覆盖：分配不足与超额拒绝冻结、虚拟客户禁止、
重复客户去重、提交顺序无关的稳定快照、幂等重复提交、版本裁决的并发修改、
冻结后迟到修改不影响持仓、失败订单无持仓但明细可查。
